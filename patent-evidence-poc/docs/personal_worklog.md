# U3 개인 작업기록 · 특허 선행기술 PoC

## 2026-09-28 · KIPRIS 실데이터 연결과 평가셋 가능성 점검

### 출발점

- `juneok` 브랜치의 BM25·Recall@K·MRR 코드는 합성 fixture에서만 동작했다.
- 이번 목표는 **키 인증 → 원본 응답 확인 → 인용 출처 확인 → 국내 인용문헌 재연결 → 작은 평가셋의 성립 여부**를 차례로 검증하는 것이었다.
- API 키는 로컬 `.env`의 `KIPRIS_API_KEY`로만 사용했다. 키 값은 출력하거나 커밋하지 않았다. API 원본은 Git에서 제외되는 `data/raw/`에 보관했다.

### 1. 첫 호출에서 발견한 문제와 수정

1. 공식 예시 출원번호 `1019950039253` 호출은 XML을 받았지만 기존 스크립트가 인용 **0건**으로 표시했다.
2. 실제 XML에는 `citationInfoV3` 요소가 15개 있었다. 기존 파서는 `item`만 읽어 전부 놓쳤다. `citationInfoV3`를 파싱하도록 고쳤다.
3. 다른 예시 `1020140170841`의 공보 조회는 `INVALID_REQUEST_PARAMETER_ERROR`를 반환했다. `applicationNumberSearchInfo`를 `/kipo-api/kipi/`와 `ServiceKey`로 호출한 것이 원인이었다. `/openapi/rest/`와 `accessKey`로 바꾸자 `resultCode=00`이 나왔다.
4. 공보 검색 결과의 반복 요소도 `item`이 아니라 `PatentUtilityInfo`였다. 이를 파서에 추가했다.
5. 터미널에서 한국어가 깨져 보였지만, 저장된 XML의 코드포인트를 검사하니 한글이 정상 보존돼 있었다. **표시 문제이며 API 텍스트 손상은 아니었다.**

### 2. 인용 유형을 확인하며 평가 정의 조정

실제 응답은 `CitationLiteratureTypeCode`와 `CitationLiteratureTypeCodeName`을 제공했다.

| 코드 | API에 나온 명칭 | 현재 해석 |
| --- | --- | --- |
| E0801 | 발송문서 | 심사 과정 문서 가능성은 있으나 출처·판단 수준 미확정 |
| E0802 | 선행기술조사보고서 | 탐색용 검색 인용 proxy 후보 |
| E0805 | 선행기술조사문헌 | 탐색용 검색 인용 proxy 후보 |
| E0806 | 출원서인용문헌이력정보 | 출원인 측 인용 가능성이 있어 proxy에서 제외 |

**결정:** E0802·E0805만으로 만든 집합도 “심사관 최종 정답”이 아니다. 당분간 **선행기술조사 관련 인용문헌 회수 proxy**라고 부른다. 인용되지 않은 문헌을 무관한 문헌으로 단정하지 않는다. 코드 기반 허용목록은 명시적으로 지정하도록 유지했다.

### 3. 10건 파일럿에서 확인한 데이터

첫 2건은 KIPRIS 공식 문의에 나온 예시다. 이전 특허에서 인용된 3건과 `센서` 검색 결과 중 연도가 다른 5건을 추가했다. **무작위 표본이 아니며 대표성을 주장할 수 없다.**

| 출원번호 | 공보 확인 | 전체 인용행 | 국내 인용 고유문헌 | E0802·E0805 국내 고유문헌 |
| --- | ---: | ---: | ---: | ---: |
| 1019950039253 | 재조회 전 | 15 | 0 | 0 |
| 1020140170841 | 1 | 10 | 3 | 3 |
| 1020060037777 | 1 | 5 | 1 | 1 |
| 1020090012972 | 1 | 11 | 3 | 3 |
| 1020110090313 | 1 | 2 | 1 | 1 |
| 1020220067549 | 1 | 3 | 2 | 0 |
| 1020200155491 | 1 | 10 | 1 | 0 |
| 1020210175204 | 1 | 0 | 0 | 0 |
| 1020200111365 | 1 | 3 | 2 | 0 |
| 1020210168398 | 1 | 0 | 0 | 0 |

- 10건 중 **4건**이 현재 탐색용 proxy의 국내 문헌을 최소 1개 갖는다.
- 그 4건의 proxy 인용은 중복 출처를 포함해 12행, **서로 다른 국내 공보 7건**이었다.
- 7개 공보 모두 번호 재조회에서 1개씩 연결됐다. 12개 연결행 모두 조회한 공보의 공개일이 기준 특허 출원일보다 앞섰다.
- 인용 0건인 두 사례는 빈 `items`를 가진 정상 형태의 응답이었다.
- 재현용 상세 연결 결과는 로컬 `data/raw/pilot_document_linkage.json`에 있다.

### 4. BM25 실측을 아직 성능으로 보고하지 않는 이유

공보 7건과 작은 검색 결과만 넣으면 positive 문헌 비중이 지나치게 높아 Recall@K가 쉽게 부풀려진다. `센서` 검색 50건에는 기준 특허 **출원 이후 공개된 문헌**이 많아 그대로 후보군에 넣으면 시간 누수도 발생한다. 2006·2009년 기준 특허에서는 출원 이전 공개 후보가 거의 남지 않는다.

따라서 이번 단계에서 확인한 것은 **API 연결·필드 파싱·국내 문헌 재연결의 성립**이다. 실데이터 BM25 성능 수치는 아직 만들지 않았다.

### 다음 루프

1. E0802·E0805가 각각 어떤 절차의 인용인지 공식 명세와 도메인 피드백으로 재확인한다. 더 강한 정답 정의가 불가능하면 `search-report citation proxy`로 고정한다.
2. IPC와 기준 시점을 활용해 **질의별 출원일 이전 공개 후보군**을 충분히 수집한다. 단순 무작위 문헌보다 같은 기술분류의 후보를 우선한다.
3. 중복·번호 연결·원문 부족·시점 위반을 자동 검증한 뒤 20~50건의 고정 평가셋을 만든다.
4. 그 평가셋에서만 B0(제목+초록 BM25) → B1(독립청구항) → B2(IPC/CPC 보정)를 동일 조건으로 비교한다.
5. 검색 실패 유형과 사람의 실제 근거 검토 흐름을 확인한 뒤 Evidence Matrix·피드백 기능 범위를 결정한다.

## 2026-09-28 · 21건 탐색 평가셋과 B0 첫 측정

### 1. 사례를 확대하며 남긴 선택 기록

- `데이터`(G06), `반도체`(H01/H10), `측정`(G01) 검색의 첫 100행에서 2010~2021년 출원, 제목·초록이 있는 후보를 추렸다.
- 고정 시드 `20260928`로 섞은 뒤 인용 XML을 차례로 확인했다. 각 분야에서 **국내 E0802·E0805 인용이 있는 7건**, 총 **21건**을 골랐다. 그룹별 검사 건수는 9·14·9건이고, 선택·탈락 사유는 로컬 `data/raw/pilot_case_sampling.json`에 저장했다.
- **인용 양성 사례를 의도적으로 고른 탐색 표본**이다. 전체 한국 특허의 인용 분포를 나타내지 않는다.

### 2. 74개 인용행을 53개 공보로 연결

- 21건에 대해 E0802·E0805 국내 인용 **74행**을 확인했다. 인용 번호 기준 고유 공보는 **53건**이었다.
- 공개공보(A/U)는 `OpeningDate`, 등록공보(B/Y)는 `PublicDate`가 채워진 경우가 있었다. 처음 `OpeningDate`만 사용하자 13행이 시점 미확인으로 표시됐다.
- 두 공개일 중 유효한 가장 이른 날짜를 기준으로 고쳐 다시 계산하니 **74/74행이 단일 공보에 연결되고 기준 출원일 이전 공개**였다. 이것은 API 필드와 번호의 기계적 검증이며 인용의 법적 타당성 판정은 아니다.
- 연결 상세는 `data/raw/pilot_document_linkage.json`; 등록공보 날짜 사례는 단위 테스트로 남겼다.

### 3. 후보 검색 페이지의 중복 발견과 수정

- `freeSearchInfo`의 `docsStart`를 페이지 번호 1·2·3으로 넣었더니 각 검색어의 100행짜리 세 결과가 거의 겹쳐, 검색어별 고유 출원번호가 약 102개뿐이었다.
- `docsStart`를 **1·101·201**로 수정해 분야당 300행을 캐시했다. 900행을 출원번호로 중복 제거하면 **895건**, 인용 정답 문헌 53건을 추가하면 **948건**이다. 잘못 수집한 겹치는 로컬 캐시는 제거했다.
- 질의마다 기준 출원일 이후 공개 문헌과 자기 문헌을 제외하니 후보 수는 **98 / 305 / 550건**(최소 / 중앙 / 최대)이었다.

### 4. B0(제목·초록 BM25) 탐색 결과

| 지표 | 21건 평균 |
| --- | ---: |
| Recall@10 | 0.651 |
| Recall@20 | 0.687 |
| Recall@50 | 0.805 |
| MRR | 0.592 |

- 74개 인용행은 질의·문헌 단위로 중복 제거하면 **53개 정답 쌍**이다. 질의별 정답은 1~5건이었다.
- 첫 정답이 50위 밖인 사례가 2건(54위, 122위)이었다. 첫 정답이 상위권이어도 다른 정답은 누락된 사례가 있어 Recall과 MRR을 함께 보아야 한다.
- 사례별 결과는 로컬 `output/real_pilot_b0.md`·`.json`에 기록했다. 원본 API XML과 평가 출력은 Git에서 제외하고, 재현 스크립트만 커밋한다.

### 해석과 다음 결정

이 수치는 **탐색용 파이프라인 진단값**이다. 세 검색어로 뽑은 후보군에 알려진 정답 53건을 주입했고, 정답이 있는 질의만 선택했다. 따라서 Recall@10 0.651을 일반적인 한국 특허 검색 성능이나 제품 성능으로 발표하면 안 된다. E0802·E0805도 선행기술조사 관련 인용 proxy이며 최종 심사관 정답은 아니다.

다음에는 분야별 검색과 시간 시점의 후보 수집을 확장하고, 청구항이 있는 후보·없는 후보가 섞여 비교가 왜곡되지 않도록 **동일한 corpus**에서 B0/B1/B2를 비교한다. 현재 948건 전체의 청구항은 모으지 않았으므로 B1/B2 수치는 아직 내지 않는다. 54위·122위 사례와 복수 정답 누락 사례부터 원문·표현 차이를 검토한다.
