# 제3자·멘토 관점 검증 게이트

## 현재 프로젝트 가설

**한국어 선행기술 Evidence Copilot**

기술 설명 또는 청구항을 입력하면:
1. 후보 선행특허를 검색하고
2. 기술요소별 근거를 연결하고
3. 사람이 관련성을 판단하며
4. 피드백 후 검색/랭킹이 개선되는지 측정한다.

AI가 신규성·진보성 또는 출원 여부를 최종 결정하지 않는다.

---

## Gate 1. 문제 자체가 실제로 존재하는가?

### 공격 질문
"특허 검색은 KIPRIS, WIPO, Patsnap이 이미 잘 하는데 왜 만들죠?"

### 현재 답
검색 기능 자체는 신규하지 않다.

우리가 검증하려는 것은:
- 한국 공개특허 데이터에서
- 단순 검색 baseline 대비
- 기술요소 분해/evidence/reranking/사람 피드백이
- 실제 historical citation retrieval을 얼마나 개선하는지

이다.

### 판정
**조건부 통과.**
실제 baseline 수치가 나오기 전까지 차별성 확정 금지.

---

## Gate 2. 평가 정답이 타당한가?

### 공격 질문
"심사관이 인용한 문헌이 정답이고, 안 인용한 문헌은 오답인가요?"

### 현재 답
아니다.

KIPRISPlus 인용문헌 데이터는 출원인 기재와 심사관 참조가 함께 포함될 수 있다.
따라서:
- citation source/division을 반드시 보존
- 명시적 whitelist로 gold 정책을 정의
- 인용되지 않은 문헌을 negative relevance로 단정하지 않음

### 판정
**이전 설계는 불충분 → 현재 수정 후 조건부 통과.**

---

## Gate 3. 20~50건으로 충분한가?

### 공격 질문
"표본 20개로 성능을 주장할 건가요?"

### 현재 답
아니다.

20~50건은:
- API/데이터 연결 검증
- baseline 난이도 확인
- 실패 유형 발견
- 개선 방향 선택

을 위한 exploratory set이다.

최종 프로젝트에서 성능 주장을 하려면 더 큰 held-out set 또는 반복 샘플링이 필요하다.

### 판정
**통과 — 단, 발표 문구 제한 필요.**

---

## Gate 4. LLM을 억지로 쓰는 프로젝트 아닌가?

### 공격 질문
"BM25로 되면 굳이 AI가 왜 필요하죠?"

### 현재 답
좋은 질문이고, 아직 필요성을 확정하지 않는다.

순서:
BM25 → IPC/CPC → embedding → reranker → LLM

baseline 오류 분석에서 다음이 확인될 때만 LLM 기술요소 분해를 넣는다.
- 복합 청구항의 여러 구성요소를 단일 query가 놓침
- 동의어/표현 차이 때문에 lexical retrieval 실패
- 긴 청구항에서 핵심요소가 묻힘

### 판정
**통과. AI 사용 자체가 목표가 아님.**

---

## Gate 5. 사람 판단 중심이라는 원래 문제와 연결되는가?

### 공격 질문
"그냥 특허 검색 프로젝트로 바뀐 것 아닌가요?"

### 현재 답
이 위험이 실제로 있다.

따라서 최종 workflow는 검색에서 끝나면 안 된다.

검색 → Evidence Matrix → 사람 관련성 판정 → 근거/결정 저장 → 필요 시 재검색

까지 연결해야 원래의 '사람 판단 지원' 주제와 정합성이 생긴다.

반대로 처음부터 넓은 IP workflow를 모두 만들면 평가가 약해지므로,
**검색/evidence를 측정 가능한 AI 코어로 두고 사람 판단 workflow가 감싼다.**

### 판정
**조건부 통과. UI/워크플로우 단계에서 반드시 재검증.**

---

## Gate 6. 경쟁 제품 대비 과장 없는가?

이미 확인된 기능:
- WIPO: 자연어 기반 AI 검색 지원
- Patsnap: claim/technical feature 분석, 여러 검색 전략, prior-art 비교/평가
- KIPRIS: 유사특허 검색

따라서 금지 표현:
- "기존에는 AI 선행기술 검색이 없다"
- "최초의 AI 특허 검색"
- "기존 서비스는 기술요소 분해를 못 한다"

대신 검증 가능한 표현:
- "한국 공개데이터에서 재현 가능한 evaluation pipeline을 구축했다"
- "동일 평가셋에서 baseline 대비 개선폭을 측정했다"
- "검색 결과와 기술요소별 근거를 연결하고 사람 피드백 전후를 비교했다"

## Go / Pivot 기준

### 계속 간다
다음 중 3개 이상이 확인되면:
- 20+ 실제 case를 안정적으로 구성 가능
- citation gold policy를 명확히 정의 가능
- BM25 Recall@K가 완벽하지 않아 개선 여지가 있음
- IPC/CPC/embedding/reranking 중 하나가 실측 개선
- Evidence Matrix가 실제 검토 시간을 줄일 가능성을 사용자/도메인 피드백에서 확인

### 범위를 바꾼다
- citation origin을 신뢰성 있게 구분할 수 없음
- 실제 corpus 구축 비용이 8주 범위를 넘음
- baseline이 이미 지나치게 쉬워 개선 여지가 없음
- 기존 제품과 비교해 프로젝트가 보여줄 추가 검증 가치가 거의 없음

### 후보를 버린다
- gold/evaluation을 객관적으로 정의할 수 없음
- 데이터 라이선스/접근 문제로 재현 가능한 실험 자체가 불가능
- 사람 판단 workflow와 검색 코어를 자연스럽게 연결할 수 없음
