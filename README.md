# U3 · 사람의 판단을 돕는 다섯 업무 도구

**업무에서 무엇을 확인하고 결정해야 하는지 놓치지 않도록 돕는 프로젝트입니다.**

반복 오류 해결, 자동화 충돌, 정책 변경 누락, 공개 전 재검토, 특허 문헌 검토의 다섯 후보를 작은 서비스로 구현했습니다. 각 후보가 어떤 문제를 해결하는지 직접 사용해 볼 수 있습니다. 최종 주제는 아직 확정하지 않았습니다.

## 먼저 사용해 보기

### 설치 없이 사용하는 방법 · 팀원에게 추천

**[U3 업무 서비스 열기](https://meeting-demo-two.vercel.app/)**

1. 왼쪽 메뉴에서 보고 싶은 업무를 선택합니다.
2. 준비된 예시로 시작합니다. 코드나 API 키를 입력할 필요가 없습니다.
3. 위쪽의 세 단계에 따라 입력 → 결과 확인 → 처리 결정을 진행합니다.
4. 판단 이유를 적고 저장합니다. 마지막 단계의 **저장 기록·내보내기**를 펼치면 기록을 가져갈 수 있습니다.

기록은 **사용 중인 브라우저에만** 저장됩니다. 팀원에게 자동으로 공유되지 않습니다. 새로고침하면 이어서 볼 수 있지만, 다른 기기나 브라우저에는 같은 기록이 나타나지 않습니다. 중요한 기록은 내보내기로 보관해 주세요. 다운로드가 안 되면 생성한 파일 내용을 복사해 저장할 수 있습니다.

## 다섯 주제, 한눈에 보기

| 주제 | 해결하려는 문제 | 사람이 결정하는 것 |
|---|---|---|
| **B-1 장애 해결 기록** | 같은 오류를 만날 때마다 처음부터 조사한다 | 이전 해결 방법을 이번에도 사용할 수 있는가? |
| **B-2 자동화 변경 검사** | 각각 정상인 자동화가 함께 실행되면 정보를 덮어쓴다 | 두 업무의 상태를 분리할 것인가? |
| **B-3 정책 변경 작업실** | 정책을 바꿨지만 안내문·설정·검사 중 일부가 이전 기준으로 남는다 | 어떤 자료를 수정하고, 변경을 완료했다고 볼 것인가? |
| **D 공개 변경 검토함** | 이전에 검토했어도 기술이 달라진 뒤 재검토할 시점을 놓친다 | 다시 검토할 것인가, 정보가 부족한가? |
| **기술 문헌 검토** | 관련 특허를 찾아도 우리 기술과 어떤 점이 비슷한지 정리하기 어렵다 | 어떤 문헌을 추가 검토하거나 제외할 것인가? |

아래의 B-1·B-2·B-3·D는 기존 아이디어를 구분하는 이름입니다.

## 1. B-1 · 장애 해결 기록

### 무엇을 하는 주제인가요?

업무 중 오류가 나면 **과거에 비슷한 문제를 어떻게 해결했는지 찾아, 이번에도 적용할 수 있는 조건을 정리하는 도구**입니다. 운영 담당자가 같은 문제를 매번 새로 조사하는 수고를 줄이는 것이 목표입니다.

현재 화면은 **공개된 실제 프로그램 오류 3건을 사용하는 체험 예시**입니다. 우리 팀이나 쇼핑몰의 실제 장애 기록은 아닙니다.

**예시:** 표 파일에 적힌 명령을 소문자로 쓰면 프로그램이 읽지 못합니다. 이전 해결 기록에서 대문자와 소문자를 모두 읽도록 고친 사례를 찾습니다. 사람은 이번 오류도 같은 조건인지 확인합니다.

### 이렇게 사용하세요

1. **문제 입력:** 준비된 `소문자 명령 인식 오류`로 해결 기록을 찾습니다.
2. **해결 사례:** 비슷한 사례를 선택하고 문제와 해결 내용을 읽습니다.
3. **처리 계획:** 이번에 적용할 조건이나 추가로 확인할 점을 적어 저장합니다.

### 지금 어디까지 되나요?

해결 기록 검색과 처리 계획 저장이 가능합니다. **프로그램을 자동으로 고치거나 복구 완료를 확인하지는 않습니다.** 다음 검증에는 실제 업무의 오류·해결 행동·성공 여부가 함께 있는 기록이 필요합니다.

## 2. B-2 · 자동화 변경 검사

### 무엇을 하는 주제인가요?

자동화는 조건에 맞으면 정해진 업무를 수행하는 기능입니다. 이 주제는 **새 자동화를 추가할 때 기존 자동화와 같은 정보를 서로 다르게 바꾸는지 확인하는 도구**입니다.

**예시:** 같은 고객에게 마케팅 후속 연락과 고객 상담이 모두 필요합니다. 두 자동화가 하나의 ‘고객 상태’를 각각 바꾸면, 나중에 실행된 값만 남아 다른 업무의 상태를 놓칠 수 있습니다. **CS는 고객 상담을 뜻합니다.**

### 이렇게 사용하세요

1. **자동화 선택:** 마케팅과 상담이 어떤 상태를 바꾸는지 확인하고 **충돌 확인**을 누릅니다.
2. **충돌 확인:** **순서별 결과 보기**로 실행 순서에 따라 남는 상태를 비교합니다.
3. **상담 상태를 따로 관리**를 누른 뒤 다시 충돌 확인과 순서 비교를 합니다. 마케팅 상태와 상담 상태가 함께 남는지 확인합니다.
4. **변경 결정:** 왜 분리하기로 했는지 적어 저장합니다.

### 지금 어디까지 되나요?

준비된 자동화 정의를 읽어 충돌 후보와 변경 전후 결과를 계산합니다. 자동화 도구 **n8n**에서도 별도로 네 가지 순서·상태 구성을 실제 실행해 확인했습니다. 다만 **공유 화면의 순서 비교는 계산이며 실제 고객 관리 시스템을 실행하지 않습니다.** 복잡한 조건이나 해석할 수 없는 정의는 보류합니다. 실제 조직의 자동화 자료를 확보해야 적용 범위를 더 검증할 수 있습니다.

## 3. B-3 · 정책 변경 작업실

### 무엇을 하는 주제인가요?

**하나의 정책을 바꾼 뒤 관련 안내와 설정이 모두 새 기준에 맞는지 확인하는 도구**입니다. 서비스 운영자가 여러 자료를 찾아 수정하고 누락을 확인하는 일을 돕습니다.

**예시:** 일반 고객의 무료배송 기준을 **5만원 → 3만원**으로 낮춥니다. 배송 정책, 자주 묻는 질문, 상담 안내, 배송비 설정이 함께 바뀌어야 합니다. VIP 배송 정책과 결제 한도는 이번 변경 대상이 아닙니다.

### 이렇게 사용하세요

1. **변경 요청:** 5만원 → 3만원 요청을 확인합니다.
2. **추천·확인:** 관련 자료가 나타납니다. 이전 금액이 남은 부분과 확인할 자료가 강조됩니다.
3. 추천 대상을 확인하고 **선택한 추천 수정 반영**을 누릅니다. **반영 결과 검사**로 누락을 확인합니다.
4. **새 기준 전후 검사 추가** 후 다시 검사합니다. 29,999원은 배송비가 발생하고, 30,000원은 무료인지 확인합니다.
5. **완료 기록:** 확인한 범위와 완료 이유를 적어 저장합니다.

**직접 확인할 예외:** 상담 안내를 선택해 ‘추천 수정 대상에 포함’을 해제하고 반영·검사하면, 상담 안내의 이전 기준이 남았다는 결과를 볼 수 있습니다. 다시 포함해 수정하고 재검사하면 됩니다.

### 지금 어디까지 되나요?

예시 파일 사본의 안내문·설정을 실제로 바꾸고 배송비를 계산합니다. 기존 **5만원 주문은 무료**라는 검사도 그대로 유지합니다. 일부 혼합 표현은 자동 변경을 보류하지만, 모든 문맥을 구분하지는 못하므로 수정 전 내용을 확인해야 합니다.

현재 추천은 자료에 지정된 관계를 사용합니다. **모든 관련 자료를 자동으로 찾아냈다는 뜻은 아닙니다.** 회사의 원본 파일이나 실제 쇼핑몰에는 반영되지 않습니다. 다음 검증에는 실제 정책·안내·설정 자료와 이들의 관계가 필요합니다.

## 4. D · 공개 변경 검토함

### 무엇을 하는 주제인가요?

기술 공개를 검토할 때 ‘이 조건이라면 괜찮다’고 판단했더라도, 나중에 기능이나 공개 범위가 바뀔 수 있습니다. 이 주제는 **지난 판단의 조건과 새 변경을 연결해, 사람이 다시 검토할 시점을 찾는 도구**입니다. 기술·연구 담당자의 검토 누락을 줄이는 것이 목표입니다.

**예시:** 외부 서비스와 연결하는 기능을 기준으로 검토했는데, 새 버전에서 관련 기능이 추가됩니다. 담당자는 이전 판단을 그대로 유지해도 되는지 다시 확인합니다.

현재 자료는 **실제 공개 SDK 변경 + 예시 판단 조건**입니다. SDK는 다른 제품에 넣어 쓰는 개발 도구입니다. 실제 회사의 내부 판단 기록을 확보한 것은 아닙니다.

### 이렇게 사용하세요

1. **기존 판단:** 당시 판단한 조건과 확인할 기술 범위를 읽거나 수정합니다.
2. **변경 확인:** **관련 변경 확인**을 눌러 조건과 연결된 변경을 봅니다.
3. **검토 결정:** 검토 요청·정보 부족 보류·추가 검토 불필요 중 하나를 고르고 이유를 저장합니다.

**최신 변경 조회**는 공개 GitHub 자료를 다시 가져옵니다. 인터넷 연결이나 조회 제한 때문에 실패하면 기존 자료로 확인할 수 있습니다.

### 지금 어디까지 되나요?

실제 변경과 지정한 기술 범위를 연결하고 검토 이유를 보관합니다. **특허·영업비밀 등 지식재산(IP)에 대한 법적 결론을 자동으로 내리지 않습니다.** 다음 검증에는 실제 내부 판단 조건과 변경 사건이 필요합니다.

## 5. 기술 문헌 검토 · 특허 검색 보조

### 무엇을 하는 주제인가요?

**우리 기술과 관련된 특허 문헌을 찾아, 추가 검토할 문헌과 이유를 정리하는 도구**입니다. 기술 담당자가 검색 결과를 읽고 비교하는 일을 돕습니다.

**예시:** 센서의 거리 데이터와 영상으로 물체를 인식하는 기술을 설명합니다. 관련 문헌의 **초록(기술 내용을 짧게 정리한 글)**을 읽고 우리 기술과 같은 점·다른 점을 확인합니다.

### 이렇게 사용하세요

1. **기술 검색:** 준비된 설명으로 **문헌 찾기**를 누릅니다. 필요하면 검색 조건을 추가합니다.
2. **문헌 비교:** 후보를 선택하고 실제 초록을 읽습니다. 상세 보기를 펼치면 문헌 정보와 **제목으로 원문을 검색하는 링크**를 확인할 수 있습니다.
3. **검토 기록:** 후속 검토·추가 정보 확인·이번 검토에서 제외 중 하나를 고르고 이유를 저장합니다.

### 지금 어디까지 되나요?

특허 정보 서비스 **KIPRIS에서 실제 조회한 문헌 2,260건의 저장본**을 검색합니다. 제목과 초록의 단어를 비교하며 ‘오브젝트·객체·물체’처럼 같은 의미로 사용하는 일부 표현을 맞춰 검색합니다.

현재 범위는 거리측정·물체 인식 관련 확보 자료입니다. **전체 특허를 실시간 검색하는 서비스는 아닙니다.** 검색 순위도 전문가의 관련성 판정이 아닙니다. 실제 특허 내용 중 보호받으려는 범위를 적은 ‘청구항’의 검토와 법적 판단은 별도로 필요합니다.

**D와의 차이:** D는 **언제 다시 판단할지**를 돕고, 이 도구는 **판단에 참고할 문헌을 찾고 정리하는 일**을 돕습니다.

## 내 컴퓨터에서 실행하고 싶다면 · 선택 사항

공유 주소로 확인할 팀원은 이 부분을 건너뛰어도 됩니다. 저장소 파일을 내려받았고 **Python 3**이 설치되어 있다면:

1. 저장소의 맨 위 폴더에서 터미널을 엽니다.
2. 아래 명령을 실행합니다.

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory topic-validation/meeting-demo
```

3. 브라우저에서 [로컬 서비스](http://127.0.0.1:8765/)를 엽니다.
4. 종료할 때는 명령을 실행한 터미널에서 `Ctrl+C`를 누릅니다.

현재 체험 화면에는 별도 패키지 설치·로그인·API 키가 필요하지 않습니다. 이 명령은 내 컴퓨터에서만 열리며, 팀 공유는 위의 배포 주소를 사용합니다. 특허를 새로 조회하는 별도 실험은 아래 개발 기록을 참고합니다.
