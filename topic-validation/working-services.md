# 실제 자료 기반 업무 서비스 · 2026-09-30

## 목적과 구현

다섯 후보를 각각 작은 업무 도구로 제공한다. 팀원 평가 수집을 주 작업으로 두지 않는다. `meeting-demo/services.html`이 현재 진입 화면이며 이전 예시 체험은 `demo.html`에 보존한다.

| 서비스 | 실제로 처리하는 입력과 결과 | 아직 확보하지 못한 범위 |
|---|---|---|
| B-1 장애 해결 기록 | SWE-bench Lite astropy 공개 사례 3건의 수정 경로·검증 테스트를 검색하고 이번 처리 계획 저장 | 쇼핑몰 예외 이력, 코드 적용 및 원본 테스트 재실행 |
| B-2 자동화 변경 검사 | 실제 n8n 실행 정의에서 추출한 HTTP 노드를 읽어 동일 URL·필드 쓰기 비교, 필드 분리 전후 순서 결과 계산, 검토 기록 저장 | 실제 고객 CRM·동적 분기·동시 실행의 전체 의미 |
| B-3 정책 변경 작업실 | 파일 사본 JSON 가져오기, 직접 편집, 일반 안내·설정 금액 변경, 배송비 함수와 경계값 검사, 파일 결과 내보내기 | 실제 회사 자료의 완전한 관계망·원본 서비스 반영 |
| D 공개 변경 검토함 | 실제 Sentry Python SDK 41개 변경 파일과 사용자 전제·경로 연결, 보류·검토 이유 보관, GitHub API 최신 버전 비교 | 실제 내부 IP 판단 기록·법적 결론 |
| 특허 기술 문헌 검토 | KIPRIS 성공 조회 문헌 2,260건 저장본에서 제목·초록 검색, IPC·공개일 조건, 표현 정규화, 검토 이유 저장 | 전체 실시간 KIPRIS 검색·청구항 기반 검증·관련도 정답 |

B-1은 공개 데이터에 맞춰 소프트웨어 장애 사례로 좁혔다. 쇼핑몰 업무 검증 성공으로 표시하지 않는다. B-2 화면은 정적 계산이며 별도 실제 n8n 4개 실행 근거와 구분한다. B-3 기본 파일은 통제 자료다. 특허 후보는 실제 문헌이며 순위는 이 앱의 단어 일치 정렬이다.

## 자료 출처와 재생성

- SWE-bench: https://huggingface.co/datasets/princeton-nlp/SWE-bench_Lite . 로컬 원본 `output/data-access/swe-rows.json`에서 요약·식별자·수정 파일·테스트 이름만 생성한다.
- n8n: `run_n8n_probe.py`의 실제 4개 실행과 `output/n8n-probe/shared-marketing-cs.json`에서 노드 추출. 공개 공유본은 URL을 example.test로 치환한다. 공식 공개 채팅 워크플로는 미지원 노드 보류 사례로 사용한다.
- SDK: https://github.com/getsentry/sentry-python/compare/2.70.0...2.71.0 . 공개 변경은 내부 IP 기록을 대신하지 않는다.
- 특허: `patent-evidence-poc/data/raw`의 기존 API 성공 캐시에서 중복 출원번호 제거. 제목·초록·IPC·날짜만 제공하며 API 키는 공개 파일에 포함하지 않는다.
- 재생성: 로컬 확보 파일을 둔 뒤 `python topic-validation/build_service_data.py`. 생성된 공개 `service-data.json`은 저장소와 배포에 포함해 다른 환경에서도 앱을 열 수 있다. 원본 확보 파일은 기존 ignore 정책을 유지한다.

## 검증 루프

1. 규칙 검사: 공유 필드 충돌, 분리 후 결과 동일, 미지원 정의·동적 URL 보류, disabled·sendBody 조건, 상담 문구 누락, 29999/30000 경계값, 기존 50000 검사 보존, 무관 결제 한도 보존, SDK 경로 연결, 실제 문헌 검색·표현 정규화 통과.
2. 독립 AI 리뷰: 비활성·본문 미전송 노드와 금액 일부 치환 문제를 수정했다. 150000/500000/15만원/십오만원/50,000,000/150,000 보호 사례를 추가했다. 사용자 배송비 설정에서 경계값 기대값을 읽는다. 입력 출처와 미저장 파일 내보내기 보류를 보강했다.
3. 브라우저: 공개 오류 근거·처리 계획 저장, 자동화 충돌 후 CS 필드 분리, 미지원 공개 LLM 정의의 결과 계산 비활성, 상담 누락·경계값 부족 후 보정·완료 기록을 확인했다. JSON 생성 결과를 파일로 보관해 다시 가져오고 3개 배송비 검사를 통과했다. D 정보 부족 보류·이유 저장과 GitHub 실시간 새로고침 성공. 특허 실제 초록·검토 기록 저장·새로고침 유지 확인. 콘솔 오류 없음.
4. 내장 브라우저의 Blob 다운로드 이벤트는 시간 초과였다. 생성 JSON 내용 검증과 파일 재입력은 성공했다. 다운로드 링크와 복사 가능한 파일 내용을 함께 제공하며 운영체제 다운로드 완료를 검증했다고 주장하지 않는다.
5. 비개발자 AI 페르소나 보정: B-2 상태 필드 분리 조작과 평문 쓰기 요약을 제공한다. 상세 JSON은 펼쳐서 편집한다. D 전제·경로는 일반 입력으로 수정할 수 있다. 각 업무에 현재 단계에 따른 다음 작업 안내, 결과 영역으로 이동, 입력 변경 시 결과 숨김을 제공한다. 실제 팀원 검증과 구분한다.
6. 모바일 390×844: 한 열 작업 공간과 주요 버튼 확인. 버튼 폭 부족으로 글자가 세로로 눌리는 문제를 최소 기준 폭으로 수정했다.

## 후속 방향

특허는 실제 데이터 기반 완성도가 가장 높다. 다음 확장은 서버에서 키를 관리하는 실시간 조회·원문 근거 확보다. B-3는 실제 정책·FAQ·설정 파일 세트를 동일 입력 형식으로 적용하고 사람이 관계를 검토하는 과정부터 확인한다. B-1은 현업 사건과 재사용 조건 정답이 필요하다. B-2는 n8n이 필수 기반은 아니며 실제 조직 정의의 읽기 전용 분석을 먼저 확장한다. D는 내부 판단 전제가 필요하고 공개 SDK만으로 법적 판단 성능을 평가하지 않는다.

입력은 브라우저 로컬 저장소 `u3-working-services-v1`에 보관된다. 회사 시스템 쓰기와 외부 전송은 없으며 SDK 공개 조회만 네트워크를 사용한다. 배포는 기존 Vercel 프로젝트에 로컬 파일 수동 배포이며 Git 연동을 새로 설정하지 않는다.
