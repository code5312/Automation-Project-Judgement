# 후보별 현업 데이터 확보 가능성 — 2026-09-30

## 판단 방법

문서에 데이터가 있다고 쓰인 것과 실제 파일·응답을 받은 것을 구분한다. `probe_data_access.py`로 작은 공개 샘플을 직접 조회하고 필드·자료 구조를 확인했다. 원문은 gitignored `output/data-access/`, 비밀정보 없는 인벤토리는 `output/data-access.json`과 배포 스냅샷에 보관한다. 공개 자료를 기업의 실제 고객·운영 판단 자료로 간주하지 않는다.

## 실제 확보한 공개 소스와 접근 조건

### B-1

[SWE-bench Lite 공식 데이터](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Lite) 공개 rows API로 첫 3건을 받았다. `problem_statement`, `patch`, `test_patch`, `base_commit`, `FAIL_TO_PASS`, `PASS_TO_PASS` 필드를 검사했다. 원본 사례는 astropy 이슈이며 주문 자료가 아니다. 테스트는 U3에서 재실행하지 않았다. 동일 원인·유사하지만 다른 해결 사례를 선정한 뒤 독립 평가해야 한다. 데이터 카드와 각 원본 저장소 라이선스를 함께 확인해야 하며 이번에는 원문 재배포 없이 로컬 분석한다.

[n8n #25066](https://github.com/n8n-io/n8n/issues/25066)은 오류·재현 요청·첨부 링크가 공개돼 있다. 신고자의 발생 횟수는 자체 측정 결과가 아니다. [#25541](https://github.com/n8n-io/n8n/pull/25541)은 미병합 제안으로 성공 정답을 만들 수 없다.

### B-2

[공식 starter kit JSON](https://raw.githubusercontent.com/n8n-io/self-hosted-ai-starter-kit/refs/heads/main/n8n/demo-data/workflows/srOnR8PAY3u4RSwb.json)을 다운로드해 노드 유형·연결·자격증명 참조 1건을 확인했다. LLM 채팅 예제이며 현재 CRM 시나리오와 다르다. 외부 서비스 연결·모델 실행을 수행하지 않았다.

[워크플로 API](https://docs.n8n.io/connect/n8n-api/workflow), [실행 API](https://docs.n8n.io/connect/n8n-api/executions)는 권한 있는 본인 인스턴스에서 정의와 실행을 조회한다. `includeData` 상세 기록·재시도 연결은 저장·삭제·가림 설정에 영향을 받는다. 노드의 URL·쿼리·표현식·코드에서 업무 자원을 식별해야 하며 정식 읽기·쓰기 정답 목록이 자동으로 제공되는 것은 아니다.

### B-3

[고정된 LibEST 자료](https://github.com/tobhey/finegrained-traceability/tree/197cf2f395e9e90636436f30d6383465cb9e9f63/datasets/LibEST) 로컬 원본 구조를 재확인했다. 요구사항 전체 파일 수와 링크가 있는 평가 행 수를 구분한다. 저장소는 GPL-3.0이고 데이터 원저자 출처가 별도 표시돼 있다. 원문 코퍼스는 배포하지 않는다. [공식 설명](https://github.com/tobhey/finegrained-traceability)은 원저자 연결 정답을 제공한다고 명시한다. 이 정답의 의미는 요구사항↔코드 관계이다.

### D

[공식 공개 결정 설명](https://blog.sentry.io/introducing-the-functional-source-license-freedom-without-free-riding/)과 [self-hosted 라이선스](https://github.com/getsentry/self-hosted/blob/master/LICENSE.md) 문서를 확인했다. 현재 blob SHA를 저장했다. 공개 이유·적용 범위·시점 자료를 연결하는 입력으로 쓸 수 있지만 과거 내부 판단을 추정하거나 Python SDK에 같은 라이선스를 적용하지 않는다. 법적 판정 정확도를 검증한 자료가 아니다.

### 특허

[KIPRIS 공식 개발 가이드](https://plus.kipris.or.kr/portal/bbs/view.do?bbsId=B0000001&nttId=1060)와 현재 승인된 키를 사용한다. 서비스별 이용 신청·승인·호출 제한을 확인해야 한다. 기존 성공 응답에서 실제 필드를 점검했다. 공개일 필드는 문헌별 누락이 있으므로 검증에 쓸 시점 기준을 명시해야 한다.

미국 대안으로 [USPTO bulk 검색 API](https://data.uspto.gov/apis/bulk-data/search)는 계정·API 키를 요구한다. 예전 PatentsView 다운로드 주소는 ODP 전환 안내로 이동했다. 무인증으로 바로 쓸 수 있다고 간주하지 않으며 이번 작업에서 새 계정·키를 만들지 않았다.

## 현업 자료를 요청할 때의 최소 단위

| 후보 | 필수 요청 묶음 | 수신 후 통과 조건 |
| --- | --- | --- |
| B-1 | 실패 실행 5건, 수정 전후 입력·규칙, 운영자 이유, 연결된 재처리 결과 | 동일 대상 ID로 실패→수정→결과가 이어지고 다른 원인·실패한 보정도 포함 |
| B-2 | 함께 실행되는 자동화 2개 정의, 같은 대상의 실행 이력, 결과 상태, 업무상 금지 조건 | 노드가 실제 읽거나 쓰는 대상과 입력/결과 확인 가능. 실행 success와 업무 정답을 구분 |
| B-3 | 실제 변경 요청 1건, 변경 전후 자료·설정·테스트, 관련/무관 검토 이유 | 담당자가 필요한 변경 범위와 완료 조건을 확정. 시스템이 못 찾은 항목도 정답에 포함 |
| D | 판단 기록 3건과 이유·전제, 이후 공개/변경 사건, 재검토 여부 | 과거 판단과 사건을 연결할 수 있고 담당자의 검토 필요/불필요 이유가 있음 |
| 특허 | 기술 설명 3개, 실제 검색 조건·문헌, 포함/제외 이유와 원문 근거 | 미관련·유사하지만 다른 문헌도 포함. 검색 전에 평가 기준 고정 |

현재 회사 협조나 인스턴스 접근 권한은 확인되지 않았다. 사람에게 자료를 요청하거나 연락한 것으로 표시하지 않는다. 후보 선정 전 이 요청 묶음을 받을 수 있는지 판단해야 한다.

## n8n 필요성 재판단

필수 기반은 아니다. 서로 다른 자동화가 공유 상태를 수정하는 가설은 실제 HTTP 클라이언트·저장소·요청 추적만으로 검증할 수 있다. n8n은 실제 도구 정의를 파싱하고 변경을 재실행하는 연동 검증 도구로 유용하다.

재점검에서 Node 24 요구 조건과 누락된 sqlite3 네이티브 바인딩을 확인했다. 격리 설치에서 sqlite3만 rebuild한 뒤 n8n 2.41.3으로 네 가지 워크플로가 통과했다. 같은 상태 필드에서는 두 순서의 결과가 달랐고 필드 분리 후 두 결과가 같았다. 정확한 저장 상태와 reset→update→update→read 요청을 확인했다. 병렬 스케줄러·현업 CRM·자동 충돌 탐지 정확도는 검증하지 않았다. n8n 자체 실행 성공을 데이터 확보 완료 조건으로 삼지 않는다.

## 팀원 피드백 전 계속할 고도화

1. 모든 후보에 입력 자료·근거·남은 데이터 제약을 보여준다.
2. B-1은 공개 해결 기록의 조건 비교, B-2는 실제 정의 파싱·공유 자원 식별을 우선한다.
3. B-3는 확보한 관계 정답에 기반한 누락·무관 후보 분석을 강화한다.
4. D는 공개 변화 수집과 과거 판단 필요성을 분명히 하고 법적 정답을 임의 작성하지 않는다.
5. 특허는 후보 확보·사람 검토 근거를 보강한다. 팀원 피드백을 사전 개선의 필수 대기 조건으로 두지 않는다.
