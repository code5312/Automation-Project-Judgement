# 독립 검토와 팀원 페르소나 점검 · 2026-09-30

## 확인의 성격

구현 담당과 별도 AI 리뷰어가 코드·근거·주장을 독립적으로 확인했다. 페르소나는 비개발 팀원, 쇼핑몰 운영자, 기술 담당자를 가정했다. 실제 팀원 인터뷰·사람의 사용성 조사·IP 전문가 검토로 표현하지 않는다.

## 1차 검토 → 수정

| 관점 | 피드백 | 반영 |
| --- | --- | --- |
| 근거 정확성 | 가상 이력과 검사·개발자 답변이 실제처럼 표현됨 | 예시 이력·검사 시뮬레이션·준비된 답변으로 알림과 버튼 수정 |
| 비개발 팀원 | 첫 행동과 이후 할 일이 불명확하고 근거 링크가 하단에 숨음 | 주제별 현재 행동·실제 확인·미확인·직접 근거 링크 제공. 의견 화면 이름 명확화 |
| 운영자 | 잘못 연결된 상품과 보류 이유가 안 보임 | 주문별 채널·용량·제안 SKU·예시 해결 SKU·보류 조건 표시 |
| 운영자 | 경계값 부족만 남아도 상담 문구 신고 버튼이 나옴 | 검사 문제별 보정 버튼 분리. 경계값만 남으면 상담 보정 버튼 숨김 |
| 기술 담당자 | 통제 실행·공개 조회·현업 성능 증거를 비교하기 어려움 | 첫 화면 카드와 주제 상단에 증거 수준·남은 관문 표시 |
| D 시나리오 | 초기 SDK 이동과 서버 유지 전제가 모순이고 특정 문구 강제 | 이동 제안→사람의 공개 범위 선택→후속 범위 확대 순서로 수정. 서버 문구 강제 제거 |

## 2차 독립 재검토 → 추가 수정

1차 P1 문제는 코드상 해소됐다는 검토를 받았다. 추가 P2 세 건을 수정했다.

- 공개 범위를 판단 이력 `scope`에 보존.
- D 도움말에 서버→SDK와 바이너리→원문 공개 분기 모두 설명.
- B-2 현재 행동 안내를 실제 버튼 이름에 맞춤.

브라우저 추가 점검에서 B-1 실패 상황인데 승인 안내가 나오던 문제를 발견해, 조건을 좁히고 재시험하라는 안내로 보정했다.

## 실행 검증 코드의 별도 리뷰

실제 n8n 실행 검증 스크립트도 독립 검토했다. 결과가 같다는 조건만으로는 양쪽 실행이 모두 잘못됐을 수 있다는 지적을 반영했다.

- 각 순서의 정확한 기대 저장 상태를 비교.
- reset→update→update→read HTTP 요청 및 쓰기 입력 기록.
- 실제 런타임 버전 확인.
- DB가 아닌 JSON 파일 상태는 `persisted_state`로 기록.
- 실패를 JSON과 종료 코드로 표시. 미설치도 실패 기록.

## 브라우저 재시험에서 확인한 것

- B-1 넓은 규칙의 잘못된 매핑 표시 → 좁은 규칙 재시험 → 승인 → 350ml 처리 → 500ml 보류.
- B-2 두 순서 비교 → CS 필드 분리 → 재시험 → 승인. 모바일 가로 넘침 없음.
- B-3 상담 문구 누락과 경계값 부족 → 상담 보정 → 경계값 문제만 남으면 상담 버튼 없음 → 경계값 보정 → 완료 승인.
- D 바이너리 공개 전제를 본인 표현으로 입력 → 기록 → 후속 원문 공개 확대에 재검토 표시. 특정 서버 문구 강제 없음.
- 주제별 실행 근거 링크가 해당 후보로 이동.
- 모바일 첫 화면 가로 넘침 없음. 도움말 Escape 닫기 확인.

## 미완료 관문

최종 독립 읽기 검토에서 새로운 P1 문제는 없었다. 표현 진단 수치의 하드코딩(P2)은 결과 JSON에서 읽도록 수정해 후속 실패·측정값 변화가 화면에 반영되게 했다.

실제 팀원의 이해도·3~5분 체험 소요 시간, 현업 예외 해결 이력, B-3의 완전한 영향 정답, D의 IP 판단 기록·전문가 정답은 아직 없다. 공개 PR 변경 목록과 병합 여부만으로 이를 대체하지 않는다. 다음 회의에서 실제 팀원 의견과 이번 페르소나 예상 문제를 대조한다.

## 최종 실행·공유 기록

n8n 설치는 완료됐으나 Node 22에서는 >=24 조건으로 거절됐다. 격리된 Node 24.21.0으로 재시도해 n8n 2.41.3 버전은 확인했지만 워크플로 import가 120초 제한을 넘었다. 실행 0건으로 실패 기록했으며 실제 n8n 검증 완료로 표시하지 않는다. B-2의 확인된 근거는 기존 HTTP·SQLite 통제 실행이다.

## 후속 루프: 필수 데이터 조사·n8n 재점검

사용자 요청에 따라 팀원 피드백 이전 고도화를 계속했다. sqlite3 누락을 복구해 실제 n8n 네 가지 워크플로가 통과했고 최신 스크립트로 재시험했다. 위 실패는 과거 시도이며 현재 성공 범위는 순차 통제 실행이다.

별도 AI가 B-1·B-2 공식 자료 경로와 필드를 조사하고 데이터 가능성 문서를 독립 검토했다. 공개 자료 확보·대리 검증·회사 접근 권한의 구분은 적절하고 새 P1은 없었다. P2 두 건을 수정했다.

- 준비된 JSON이 판단 수정 후 낡은 상태로 내려받아지던 문제: 저장 상태 변경 때 준비 파일 무효화. 브라우저에서 초기화 후 이전 링크 제거와 새 JSON 단계 0 확인.
- n8n 최종 코드와 실행 기록 시점: 최신 코드 재실행으로 node_version/sqlite_dependency와 4개 실행 기록 확인.

실제 회사 협조·팀원 인터뷰·IP 전문가 정답은 새로 확보하지 않았다. 현재 자료와 확보에 필요한 묶음은 `data-feasibility.md`에 정리했다.
