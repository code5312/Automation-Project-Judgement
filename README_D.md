## **D. 사람 판단 중심 지식 재산 업무 자동화**

> **“AI가 지식재산 관련 결론을 대신 내리는 것이 아니라, 사람이 판단해야 하는 순간을 먼저 찾아 필요한 근거를 준비하고, 판단 이후 후속 업무와 재검토까지 자동으로 연결할 수 없을까?”**
> 

## 어떤 문제인가?

기업의 지식재산 업무에서는 제품 출시뿐 아니라 **논문·학회 발표, 오픈소스 공개, 신규 기술 개발, 기존 기술의 공개 방식 변화** 등 다양한 상황에서 지식재산 담당자의 판단이 필요하다.

예를 들어 신규 기술이 개발됐더라도 담당자가 이를 인지하지 못하면 IP 검토 자체가 시작되지 않을 수 있다. 또한 과거에는 영업비밀로 유지하기로 결정한 기술이라도 이후 제품 구조나 외부 공개 방식이 바뀌면 당시 판단을 다시 검토해야 할 수 있다.

따라서 핵심 문제를 단순히 **“AI가 IP 판단을 잘할 수 있는가?”**로 보지 않고,

**언제 사람이 판단해야 하는지 발견하고 → 판단에 필요한 자료를 준비하고 → 판단 결과를 후속 업무로 연결하고 → 이후 상황이 달라지면 다시 검토하게 하는 과정**

전체의 자동화 문제로 본다.

---

## 기존 방식과 차별화하려는 지점

단순히 **AI가 분석하고 사람이 최종 승인하는 Human-in-the-loop 구조 자체는 차별점으로 보기 어렵다.**

따라서 이 주제에서는 다음 네 과정을 하나의 폐쇄형 업무 흐름으로 연결하는 것을 핵심으로 한다.

**판단 순간 탐지 → 판단 근거 생성 → 판단 이유·전제 저장 → 전제 변화 시 재검토**

즉, 사람이 직접 IP 검토 요청을 등록한 이후부터 자동화하는 것이 아니라, **업무 데이터에서 검토가 필요한 상황 자체를 먼저 발견하는 것**에서 시작한다.

---

## 우리가 생각한 자동화 흐름

```
제품 출시·논문·오픈소스 공개·기술 변경 등의 사건 발생

→ GitHub / Jira / 기획문서 / 기존 IP 기록 분석

→ 사람의 IP 판단이 필요한 사건인지 탐지

→ 관련 기술 변화·과거 결정·유사 사례·누락 정보를 수집

→ 판단 카드 생성

→ IP 담당자 최종 판단

→ 관련 검토·승인·후속 업무 자동 생성 및 추적

→ 판단 당시 이유와 전제 저장

→ 이후 제품·기술 상황 변화 감시

→ 기존 판단의 전제가 달라지면 재검토 요청
```

### 예시

3월에 특정 기술에 대해 다음과 같이 판단했다고 가정한다.

> **결정:** 영업비밀 유지
> 
> 
> **판단 전제:** 기술 구현이 서버 내부에 있어 외부에서 확인하기 어려움
> 

이후 9월 제품 구조가 변경되어 해당 기술이 외부 SDK에 포함될 예정이라면 시스템은

> 🟠 **과거 판단의 핵심 전제가 변경됐을 가능성이 있습니다.**
> 

라고 알려주고 **IP 담당자에게 재검토 업무를 생성**한다.

시스템이 “이제 특허를 출원해야 한다”고 결정하는 것이 아니라, **과거 판단 당시의 전제가 현재도 유지되는지를 확인해 사람에게 다시 판단을 요청하는 구조**다.

---

## 판단 카드에 포함할 정보

| 구분 | 내용 |
| --- | --- |
| 기술 변화 | 이번 버전에서 새롭게 발생하거나 수정된 기술 |
| 기존 IP 결정 | 동일·유사 기술에 대한 과거 검토 결과 |
| 유사 사례 | 기존 사내 IP 검토 사례 |
| 추가 확인 정보 | 외부 공개 일정, 오픈소스 포함 여부, 공동개발 여부 등 |
| 위험 신호 | 미검토 신규 기술, 과거 판단 전제 변화 가능성 |
| 판단 요청 | 어떤 내용을 사람이 확인해야 하는지 질문 형태로 제시 |

핵심은 AI가 결론을 내리는 것이 아니라 **사람이 바로 판단할 수 있는 상태까지 정보를 정리해주는 것**이다.

---

## AI는 어디에 필요한가?

AI는 정형적인 상태 확인보다 **서로 표현 방식이 다른 자료 사이에서 의미를 연결하는 영역**에 사용한다.

| AI 활용 | 일반 로직 |
| --- | --- |
| 기술적으로 의미 있는 변화 요약 | 이전/현재 버전 비교 |
| 신규 변경과 기존 IP 기록 의미 연결 | 검토 완료 여부 확인 |
| 과거 판단 이유를 전제 형태로 구조화 | 담당자·승인 상태 관리 |
| 현재 변화와 과거 판단 전제 비교 | 업무 생성 및 알림 |
| 판단 근거·확인 질문 생성 | 검토 완료/미완료 상태 추적 |

최종적으로 **발명 여부, 특허 출원 여부, 영업비밀 유지 여부, 공개 가능 여부 등 법률적·전략적 결정은 사람이 수행**한다.

# 8주 MVP 범위

전체 지식재산 업무를 구현하기보다는 **사람 판단이 필요한 두 가지 사건**으로 범위를 제한한다.

### ① 외부 공개 전 IP 검토 누락 탐지

제품 출시·논문·오픈소스 공개 등을 하나의 **외부 공개 사건**으로 보고, 공개 전에 아직 IP 검토가 이루어지지 않은 신규 기술이 있는지 확인한다.

예를 들어 제품 v3.2 출시 전에 개발 변경 11건을 분석한 결과

| 결과 | 건수 |
| --- | --- |
| 기존 IP 검토와 연결 | 7건 |
| 중요 기술 변화가 아닌 항목 | 2건 |
| 신규 기술이지만 IP 검토 기록 없음 | 🔴 1건 |
| 기존 판단의 전제 변화 가능성 | 🟠 1건 |

처럼 보여주는 형태다.

### ② 과거 IP 판단의 전제 변화 재검토

과거 특허·영업비밀·보류 등의 판단과 함께 **판단 이유 및 전제**를 저장하고, 이후 기술이나 외부 공개 방식이 변화하면 해당 전제가 여전히 유효한지 확인한다.

## MVP 구성

| 구분 | 범위 |
| --- | --- |
| 업무 사건 | 제품 출시·논문·오픈소스 공개 일정 |
| 개발 데이터 | GitHub/Jira 형태의 합성 변경 데이터 |
| IP 데이터 | 가상 IP 검토 기록 |
| 변화 유형 | 신규 기술 / 단순 변경 / 기존 기술 수정 / 외부 노출 방식 변화 |
| 주요 기능 | 판단 사건 탐지 → 판단 카드 → 사람 판단 → 업무 생성 → 전제 저장 → 재검토 |
| 제외 | 실제 특허 신규성·침해·특허 가능성 등에 대한 법률 판단 |

## 평가 방법

| 평가 항목 | 지표 예시 |
| --- | --- |
| 판단 사건 탐지 | 정밀도, 재현율, 검토 사건 누락률 |
| 불필요한 호출 | 실제로 검토가 필요하지 않은데 사람에게 요청한 비율 |
| 판단 카드 품질 | 필요한 근거가 포함된 비율 |
| 기존 기록 연결 | 관련 과거 결정 연결 정확도 |
| 재검토 기능 | 판단 전제 변화 탐지 정확도 |
| 업무 효과 | 판단 준비시간 감소, 누락 검토 감소 |
| 후속 자동화 | 판단 이후 업무 생성·추적 정확도 |

## 8주 프로젝트에서의 핵심 데모

최종 발표에서는 다음 장면을 하나의 흐름으로 보여주는 것을 목표로 한다.

**제품 출시 예정 → 개발 변경 데이터 분석 → 미검토 신규 기술 탐지 → 판단 카드 생성 → 사람이 ‘영업비밀 유지’ 선택 → 판단 이유·전제 저장 → 이후 외부 공개 방식 변경 → 전제 변화 탐지 → 재검토 요청**

즉, 단순히 AI가 텍스트를 분석하는 화면이 아니라 **판단 전과 판단 후의 업무 흐름 전체가 실제로 움직이는 것을 보여주는 것**이 핵심이다.

## 현재 고민

> ⚠️ **멘토링에서 확인하고 싶은 부분**
> 

**① 실제 기업의 지식재산 업무에서 ‘검토가 필요한 사건을 놓치는 문제’가 충분히 중요한 Pain Point인지**

**② GitHub/Jira 등의 변경 정보와 기존 IP 검토 기록을 연결하는 범위를 8주 안에 어느 정도까지 구현하는 것이 적절한지**

**③ 실제 기업 IP 데이터를 확보하기 어려운 상황에서 합성 개발 데이터와 가상 IP 기록을 활용한 MVP도 현업 업무자동화 프로젝트로 충분한지**

**④ ‘판단 순간 탐지 + 판단 근거 준비 + 결정 전제 저장 + 전제 변화 재검토’라는 흐름이 기존 IP 업무 솔루션과 비교했을 때 프로젝트 수준에서 충분한 차별성을 가지는지**
