# 평가 세트 (docs/PIPELINE.md 단계 2)

## `ev_battery_cooling_v1.json`

**상태: 확정됨.** 담당자 mingyu가 AI(Claude) 초안 라벨 40건을 검토하고 2026-10-02에 그대로 확정했다. `docs/PIPELINE.md` 단계 2의 "평가 세트 20~50건 라벨링 (사람 판단 기준)" 체크박스는 이 확정을 반영해 체크되어 있다.

- **특허 데이터 자체는 실제 데이터다.** `outputs/kipris_patents_*.csv`(2026-09-28, 실제 KIPRIS Plus 호출 결과, 검색어 "전기차 배터리 냉각")를 출원번호 기준으로 중복 제거해 40건을 추렸다. 가짜 특허 데이터는 생성하지 않는다는 원칙(`README.md`)을 지켰다.
- **라벨(`human_label`, `label_rationale`)은 AI가 제목·초록·IPC를 읽고 독립적으로 판단해 초안을 작성**했고(시스템이 매긴 `relevance_score`/`review_priority`를 베끼지 않음 — 베끼면 시스템이 자기 자신을 검증하는 순환 논리가 됨), 담당자가 그 초안을 검토해 그대로 확정했다.
- 라벨은 "전기차 배터리 냉각"이라는 `review_technology` 기준으로만 판단했다. 배터리 일반·전기차 일반 특허라도 냉각/열관리가 핵심이 아니면 낮음으로 분류했다.
- **현재는 40건·고정 JSON 파일로 수동 관리하는 v1이다.** 평가 세트가 더 커지거나(단계 3 트리아지 평가, LLM 분류 프롬프트 평가 등) 반복 라벨링이 필요해지면, 이 고정 JSON을 LLM 보조 라벨링이나 다른 저장 방식으로 교체하는 것을 검토한다 — 지금 단계에서는 과설계를 피하고 이 형태를 유지한다.

### 다음에 평가 세트를 바꿀 때

1. 새 항목을 추가하거나 라벨을 고치면 `python -m ipauto.cli evaluate`로 재측정하고, 결과를 `docs/PIPELINE.md`의 "평가 지표 기록" 표에 새 행으로 남긴다.
2. 세트 성격이 바뀌면(예: 다른 기술 분야 추가) 파일명에 버전을 올리고(`_v2` 등) 이 README의 출처·확정 기록도 함께 갱신한다.

### 형식

```json
[
  {
    "발명의 명칭": "...", "출원번호": "...", "출원인": "...", "IPC": "...",
    "등록상태": "...", "초록": "...",
    "review_technology": "전기차 배터리 냉각",
    "human_label": "높음 | 보통 | 낮음",
    "label_rationale": "라벨을 매긴 이유 한 줄"
  }
]
```

`python -m ipauto.cli evaluate [평가세트.json]`으로 현재 스코어러의 `review_priority`와 `human_label`을 비교해 정확도·혼동행렬을 출력한다(`src/ipauto/evaluation.py`).
